# Pi Webdesk feasibility preregistration

**ASSUMPTION — selection:** Pi Webdesk exercises a coding agent with Pi-owned sessions, file tools, approval dialogs and process trees. This document preserves the bounded feasibility design; use [the native guide](native-guide.md) for the current integration.

**TARGET — fixed exercise before execution:** use the installed Pi 0.84.2 runtime, Webdesk's actual RPC bridge, supervisor and supervised policy extension, one disposable Git repository per attempt, and an explicit local scripted provider. Run exactly two fresh baseline repetitions, a denied write, and interruption after a shell command's first observable write. No model-provider request or provider credential is needed. Baseline turn one reads README and writes `notes.txt` with `alpha\n`; turn two reads it, edits `alpha` to `beta`, and reads it back. The denied attempt proposes `protected.txt` and must leave it absent. The interrupted command writes `started\n`, sleeps, then would append `finished\n`; abort after independent observation of the first write, retain that partial effect, and verify process cleanup.

**TARGET — fidelity and evidence:** use supported Pi tool-definition overrides that delegate to the original exported implementations. A durable local gate before delegation tests whether the original callback can wait for external dispatch permission. Keep original Webdesk approval handling ahead of this gate; approve only exact preregistered calls. Retain raw scripted-model contexts, interception records, Pi's own session file, bridge events, independent filesystem snapshots and owned-process observations. Never use bounded UI event projections as the sole evidence. Copy artifacts out before deleting the lease. Record denied dispatch and partially observed shell effects separately from execution and cleanup.

**CURRENT — scope limits:** this harness is integration-owned and emits its own closed feasibility report; it does not yet emit a Trialyard native bundle. It bypasses the Webdesk daemon/browser and its worktree manager, creates its own disposable Git fixture, and uses a deterministic provider instead of testing model quality. Installed dependencies are reused; selected source and built bridge bytes are recorded, but the full external Pi dependency closure is not a portable native input inventory. No paid run, human onboarding replay, external assessment handoff, merge or deployment is authorized by this exercise.

**TARGET — decision:** report whether supported interception can preserve Pi's original loop/tools, which lifecycle boundaries actually worked, how much integration-only code was needed, and whether a native continuation adapter can reuse the existing routed-tools contract. Do not replace the loop or broaden core contracts just to declare the candidate supported. Retain unsuccessful attempts and repair history.
